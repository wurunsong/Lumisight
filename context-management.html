Lumisight：Agent 上下文管理视图

这张图单独描述“上下文如何入账、何时判断过大、如何压缩、何时落盘、最终如何投影给模型看”。它不重复主架构页的协议与工具细节，而是专门聚焦上下文账本与 5 层压缩流水线。

1. 上下文主链路

用户输入 / 工具结果
→
Session Ledger 入账
→
大结果落盘
→
Snip / Micro-Compact
→
读时投影
→
Auto-Compact
→
Prompt 视图
当前上下文链路的判断单位不是“原始字符串列表”，而是结构化账本：每条 entry 会记录来源类型、token 估算、是否可裁剪、是否可重取、是否已有磁盘 artifact。
无论前面是浏览器调试页还是 macOS 客户端壳，最终消费的都是这条上下文主链路产出的同一套事件与答案视图，客户端外壳不会改写核心上下文决策。

2. 会话账本结构

2.1 会话状态层

  • AgentConversationManager 继续负责会话状态机、epoch、中断、todo 与等待态 TTL。
  • 它通过 AgentSessionContextStore 抽象暴露保存/恢复接口，保存的不再只是 List<AgentContextItem>，还会附带 AgentContextSession。
  • 作用：让“会话状态”和“上下文账本”分层，不再所有逻辑都堆在一个列表里。

2.2 上下文账本层

  • AgentContextSession 是会话级账本，内部持有多条 AgentContextEntry。
  • 每条 entry 会标记 kind、priority、tokenEstimate、artifactRef、compactable、retriable。
  • 作用：后续 Snip、Micro-Compact、Projection 都有统一抓手。

2.3 Artifact 层

  • 大结果通过 FileAgentContextArtifactStore 写入 .lumisight/context-artifacts。
  • prompt 中只保留 preview、artifact path、artifact id 和元数据。
  • 作用：完整正文不丢，但不再直接撑满模型上下文。

2.4 Projection 层

  • 模型调用前不直接拿完整账本，而是由 DefaultAgentContextManager 动态生成“本轮视图”。
  • 决策、复核、最终回答三种 prompt 都各自走投影。
  • 作用：保留真实历史，同时避免每轮都把所有旧上下文原样塞进去。

3. 怎么判断“上下文太多了”

3.1 判断基线

  • 当前主要按 token 估算而不是按字符数判断；入口是 AgentContextEntry.tokenEstimate。
  • 预算上限由 lumisight.agent.context.effective-context-window 决定。
  • 这个值就应该按模型能力调，不同模型上下文窗不同，这里必须可配置。

3.2 两级投影阈值

  • projection-soft-tokens：超过后开始主动折叠旧内容。
  • projection-hard-tokens：超过后继续强裁，优先保高优先级 entry。
  • 作用：在真正触发全量摘要前，先尽量保住细节上下文。

3.3 Auto-Compact 阈值

  • 触发阈值不是写死常量，而是：effective-context-window - response-reserve-tokens - auto-compact-buffer-tokens。
  • 也就是说，模型越大，只要把 effective-context-window 调大，整个压缩触发点会自然后移。
  • 作用：为不同模型留出可配置的输出空间和安全缓冲区。

4. 怎么判断“大结果”

4.1 单条结果阈值

  • single-artifact-bytes：单个上下文 entry 超过这个大小，就直接落盘。
  • 默认值是 50KB。
  • 适合控制单个 cat / grep / 大 diff 输出。

4.2 单轮总量阈值

  • tool-message-bytes：同一批工具结果累计超过这个大小，会优先把最大的几条转成 artifact。
  • 默认值是 200KB。
  • 适合限制“一次工具批次”整体噪音，而不只是盯单条结果。

4.3 Preview 阈值

  • preview-bytes 决定 prompt 中保留多少预览内容。
  • 默认值是 2KB。
  • 作用：模型仍能看到结果大意，但不会因为 artifact 回填又重新爆上下文。

5. Claude Code 风格 5 层压缩流水线

5.1 大结果存盘

  • 触发：单条或单批工具结果超过字节阈值。
  • 处理：全文写磁盘，账本中保留 preview 与 artifact 引用。
  • 输出：完整结果仍可追溯，但 prompt 只看到精简视图。

5.2 Snip 老对话

  • 触发：历史对话累计 token 达到 snip-trigger-tokens。
  • 处理：较早、低优先级 conversation entry 被直接移除，并写入 boundary marker。
  • 输出：释放空间，且记录本轮释放了多少 token。

5.3 Micro-Compact 工具结果

  • 触发：账本过大，或距离上次有效投影已过 micro-compact-stale-minutes。
  • 处理：只裁剪可重取工具结果，保留最近 N 条原文和更老条目的 compact marker。
  • 输出：模型知道“这里有内容被裁掉了”，需要时可重跑工具。

5.4 读时投影

  • 触发：本轮决策/复核/最终回答前。
  • 处理：不改原始账本，只在调用模型的那一刻按预算动态折叠旧上下文，优先保控制态、近期对话和高优先级证据。
  • 输出：给模型的是“当前这一轮最值钱的一份上下文视图”，尽量在不做全量摘要的前提下保住更多细节。

5.5 Auto-Compact 全量摘要

  • 触发：读时投影后仍然超过 effective-context-window - response-reserve-tokens - auto-compact-buffer-tokens。
  • 处理：把更早历史压成结构化摘要，再恢复最近访问的热文件/热证据；连续失败次数超过上限后不再无限重试。
  • 输出：在上下文已经明显超限时，用一次更重的压缩换回可继续工作的 prompt 空间。

6. 当前可调参数

推荐先调这几类：
1. 模型窗口：effective-context-window、response-reserve-tokens、auto-compact-buffer-tokens
2. 大结果策略：single-artifact-bytes、tool-message-bytes、preview-bytes
3. 对话裁剪策略：snip-trigger-tokens、snip-target-tokens、snip-keep-recent-conversation
4. 投影/裁剪策略：projection-soft-tokens、projection-hard-tokens、micro-compact-keep-recent、micro-compact-stale-minutes
5. 恢复策略：post-compact-token-budget、post-compact-max-restore-entries、post-compact-max-tokens-per-entry、post-compact-skill-token-budget
