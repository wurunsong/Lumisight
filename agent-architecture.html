Lumisight：Java 代码智能 Agent 架构

定位：先离线构建外挂知识库（Nebula + Milvus），再开发在线 Agent 运行时，聚焦工程编排与可解释输出；当前已形成“图谱查询 + 向量增量入库 + 配置稳定化”闭环。

1. 阶段化主流程（先离线，后在线）
离线解析 Java 仓库
→
构建 Milvus 向量索引
→
构建 Nebula 关系图谱
→
启动 Agent Runtime
→
编排 + 工具调用 + 记忆 + Skill
→
输出结论与证据链
2. 在线 Runtime 端到端执行流
用户请求 /agent/query
→
Planner 任务拆解
→
SkillRuntime 注入策略
→
Tool Router 选择工具
→
Milvus/Nebula 查询
→
Reviewer 证据审查
→
结构化答案返回
3. 核心模块分层（在线）

A. 接入层（API）

  • 统一前缀：`/api/lumisight`
  • KG 接口：build/view/query + 单节点查询
  • Vector 接口：code_chunk/symbol_doc/auto/repo ingest

B. 编排层（Agent Core）

  • core 模块集中管理 AI 与向量配置
  • API 显式导入 core 配置，规避同名冲突
  • 以开关控制向量链路启停与懒加载

C. 工具层（Tools）

  • VectorIngestService：自动切片 + 批量入库
  • Repo 方法解析 + `git diff` 增量更新
  • Nebula 查询语法修正后稳定返回结构

D. 能力层（Memory + Skills）

  • symbol_doc 生成器接口保留可替换实现
  • 双集合注入：`code_chunk` 与 `symbol_doc`
  • 配置降级：关闭非必需模型与音频自动配置
4. 外挂知识库（离线构建）

Milvus（向量知识）

  • code_chunk：方法级代码片段向量
  • symbol_doc：符号职责文档向量
  • 双集合 Bean + `@Qualifier` 显式注入
  • 元数据：repo/file/qualifiedName/git

Nebula（结构知识）

  • 节点：module/package/class/method
  • 边：contains + method calls
  • repo_meta 记录构建基线提交

契约与治理

  • 统一 Query Contract
  • 索引版本与新鲜度标记
  • 不可用降级与回退策略
  • 配置收敛到 core，API 仅做导入与开关控制
5. 第一阶段：知识图谱构建步骤（当前重点）
输入 repoRoot
→
读取 git branch + HEAD
→
main/master 门禁
→
判定全量/增量
→
JavaParser 解析 AST
→
写 Nebula + 写 Milvus(双集合)
→
更新 repo_meta 基线

5.1 Nebula 构建环节

  • space 规则：`kg_工程名`
  • schema 自动创建并等待生效
  • 首次全量，后续按 git diff 增量
  • 删除策略：逻辑删除 `status=1`
  • ID 规则：节点/边统一哈希生成

5.2 Milvus 构建环节

  • code_chunk 入库（方法级文本）
  • symbol_doc 入库（AI说明文档）
  • 支持 repo 解析与 `git diff` 增量入库
  • AI 生成接口已预留，可替换
  • 向量与结构通过 qualifiedName 对齐

5.3 第一阶段验收标准

  • Nebula 全量/增量稳定可重跑
  • view/query 能稳定返回结构数据
  • Milvus 双集合可持续入库并支持懒加载开关
  • 可支撑后续问答/修复检索底座
面试讲解建议：先讲整体架构，再强调当前阶段是“离线知识库构建”，把流程、规则、增量策略和可追溯性讲清楚。
