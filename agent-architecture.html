Lumisight：Java 代码智能 Agent 架构

定位：支持“离线知识库增强模式”与“纯 Agent 本地调试模式”双路径；当无 Nebula/Milvus 环境时可仅启动在线 Agent Runtime，通过本地工具链与事件流完成可解释编排。

2.1 Agent Loop 细化流程（当前实现）

入口与模式

  • 入口类：`CodeAssistantAgentService`
  • 请求校验：`AgentRequestValidators.validate`
  • 模式：`NORMAL` 直接循环；`PLAN` 先产出计划事件
  • 上下文作用域：`AgentToolRuntimeContext.open(repoRoot, limit)`

循环决策

  • 轮次上限：`MAX_TOOL_ROUNDS`
  • 每轮由模型输出 JSON：`action/toolName/args/finalAnswer/askUserQuestion`
  • `action=tool`：按权限调度工具执行
  • `action=ask_user`：输出反问事件并等待用户补充
  • `action=final`：直接结束并返回最终结论

事件输出

  • 中间过程事件：`PLAN/TOOL_CALL/TOOL_RESULT/ASK_USER`
  • 文本流事件：`TOKEN`（模型流式分片）
  • 收敛事件：`FINAL`
  • 异常事件：`ERROR`（工具未注册、权限不足、解析回退）
3. 核心模块分层（在线）

A. 接入层（API）

  • 统一前缀：`/api/lumisight`
  • KG 接口：build/view/query + 单节点查询
  • Vector 接口：code_chunk/symbol_doc/auto/repo ingest
  • Agent SSE 接口：`POST /api/lumisight/agent/stream`

B. 编排层（Agent Core）

  • 核心类：`CodeAssistantAgentService`（单类主循环）
  • 运行模式：`AgentRunMode.NORMAL` / `AgentRunMode.PLAN`
  • 支持 `ask_user` 动作，信息不足时反问而非硬结束

C. 工具层（Tools）

  • Tool Registry 按权限与类别动态调度
  • Hybrid Vector 并发召回（代码 + 注释向量）
  • 可组合接入图谱查询与源码定位工具

D. 输出与事件层

  • 统一事件模型：`AgentEvent`
  • 事件类型：PLAN/TOOL_CALL/TOOL_RESULT/ASK_USER/TOKEN/FINAL/ERROR
  • 可用于前端、CLI、服务间实时订阅
3.1 运行策略与降级（今日更新）

计划模式

  • `PLAN` 模式首轮先输出执行计划
  • 后续按循环决策执行工具调用
  • 适用于复杂任务和可解释流程场景

反问策略

  • 动作：`ask_user`
  • 当上下文不足时主动向用户请求补充信息
  • 避免误判为 `final` 导致错误收敛

异常与回退

  • 工具未注册：事件 `tool_error/unknown_tool`
  • 权限不足：事件 `tool_error/permission_denied`
  • 决策解析失败：回退到最终回答分支
4. 外挂知识库（离线构建）

Milvus（向量知识）

  • code_chunk：方法级代码片段向量
  • symbol_doc：符号职责文档向量
  • 双集合 Bean + `@Qualifier` 显式注入
  • 元数据：repo/file/qualifiedName/git

Nebula（结构知识）

  • 节点：module/package/class/method
  • 边：contains + method calls
  • repo_meta 记录构建基线提交

契约与治理

  • 统一 Query Contract
  • 索引版本与新鲜度标记
  • 不可用降级与回退策略
  • 配置收敛到 core，API 仅做导入与开关控制
5. 当前阶段：Agent 核心流程完善（当前重点）
接收请求（NORMAL / PLAN）
→
模型决策 action
→
工具执行与结果回填
→
信息不足触发 ask_user
→
事件流输出（TOOL/TOKEN/FINAL）
→
SSE 持续推送到客户端

5.1 决策与执行闭环

  • 每轮输出结构化决策：`tool / ask_user / final`
  • 工具结果进入下一轮上下文，直到收敛
  • 支持 PLAN 先规划，再执行
  • 保留最大轮次，防止无限循环
  • 主类只保留核心 loop，不耦合增强逻辑

5.2 工具链编排策略

  • 优先走混合向量工具（代码+注释并发召回）
  • 图谱和源码查询由链路硬编排衔接
  • 按工具类别与权限统一注册和调度
  • 便于后续多 Agent 复用和治理
  • 为 Advisor 化上下文增强预留边界

5.3 当前阶段验收标准

  • 可稳定输出 PLAN / TOOL_CALL / TOOL_RESULT / FINAL
  • `ask_user` 在信息不足时可正确中断并反问
  • SSE 能实时消费事件，不只返回最终文本
  • 核心流程和上下文增强职责边界清晰
6. 今日架构增量（2026-05-29）

6.1 主循环治理

  • 新增 `Verifier` 复核环：`final` 先校验再收敛
